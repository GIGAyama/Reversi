# note 入稿メモ（リバーシ）

連載「教室で使えるかもしれないもの作り」向けの紹介記事一式です。

- `reversi-note-article.md` … 記事本文。note にそのまま貼れる形
- `images/` … 実際にブラウザで操作して撮った画面 22 点

---

## 貼るまえに直すところ

1 か所だけあります。

- タイトルの `#◯` が連載番号のプレースホルダのままです。推測で埋めていません。前回が #9（Qalc）なら `#10` になりますが、そこは書き手の方で確定してください。

このほか、記事には教室での出来事を実体験としては一切書いていません。「こうなればいいと思って作った」までにとどめています。実際に使ってみた様子は、書き手の方で足す前提です。

## note に貼る手順

1. note で新しい記事を作る
2. `reversi-note-article.md` の 1 行目（`# 教室で使える…`）をタイトル欄に入れる。本文には入れない
3. 2 行目以降を本文欄に貼る。見出しの `##` は note のエディタで大見出しに変換される
4. 画像は自動では入らないので、`images/` から手で1点ずつアップロードする。本文の `![...](images/xx.png)` の位置にそのまま差しこむ
5. 画像の直後にある一行の説明を、note のキャプション欄へ移す。本文からは消す
6. ハッシュタグ欄に `#GIGAスクール` `#小学校` `#ICT教育` `#リバーシ` `#Chromebook` あたりを入れる
7. 見出しから目次が自動で作られるので、目次の表示をオンにする

## 記事に書いた数字と、その出どころ

- 盤面サイズが 4・6・8・10・12 の 5 とおり … `src/lib/reversi.js` の `isValidBoardSize`（4 以上 12 以下の偶数）。実際に 4 と 12 に変えられること、5 が赤字ではねられることを撮影中に確認（08 / 09 / 10）
- めくれる間隔が 0.1 秒ずつ … `src/App.jsx` の `delay: i * 0.1`
- パスの案内が 1 秒半 … `src/App.jsx` の `setTimeout(..., 1500)`
- 「待った！」に回数の制限がない … `src/App.jsx` の `handleUndo` に上限の判定が無い
- 音声ファイルを 1 つも持っていない … `public/` に音の素材が無く、`playTone` が Web Audio で合成している
- 記録を端末に残さない … リポジトリ全体を検索して `localStorage` `sessionStorage` `indexedDB` の使用が 0 件
- 外へ出ていくのは fonts.googleapis.com と fonts.gstatic.com だけ … `index.html` の CSP（`connect-src 'self'`、`style-src` と `font-src` にだけ Google Fonts がある）。撮影した環境自体が Google Fonts へ到達できないため、塞がれた状態で全画面が動くことをそのまま確認している
- 横 320px で横スクロールが出ない … 撮影時に実測（`scrollWidth 320 / clientWidth 320`）
- 一度ひらけば圏外でも起動する … 配信サーバを立てて 1 回ひらいたあと、サーバをプロセスごと止めて再読み込みし、盤面の 64 マスが出ることを確認。サーバが止まっていることは `curl` が接続を拒否されることで確認済み
- 初回に読み込む JS が約 165KB … `dist/assets` の JS が 165,361 バイト（gzip で約 52KB）
- 中核ロジックのテスト 14 件 … `npm test` の出力

`README.md` と `MANUAL.md` の記述とも突き合わせています。今回は食いちがいはありませんでした。

## 撮り直すときの手順

撮影用の一式は `.tmp-shots/` に置いて、納品時に消しています。同じものを作り直す場合は次のとおりです。

1. `npm i --no-save playwright` と `npm run build`
2. 別のターミナルで `node <skill>/scripts/serve.mjs dist 4180 /Reversi/`
3. シナリオを書いて `node <skill>/scripts/capture.mjs <シナリオ> --base http://127.0.0.1:4180/Reversi/ --out <出力先>`

撮影時に気をつけたところを残しておきます。

- ボタンの文字にふりがなが混ざっているので、`<rt>` を落としてから照合する。`capture.mjs` の `click()` はそうなっている
- 盤面のマスは `role="gridcell"` で、ボタンではない。`aria-label`（「3だんめ 4れつめ ここに おける」）で探して押す
- 勝敗の画面を撮るには実際に終局まで打つ必要がある。両者とも同じ選び方をすると引き分けになりやすいので、黒は角に近い手、白は真ん中寄りの手を選ばせた。今回は 48 対 16 で黒の勝ち
- 更新の帯は、配信中の `dist/sw.js` の版を上げて `registration.update()` を呼べば本物が出る。`dist/` はビルドの生成物なので、書き換えても原本には影響しない
- 記事に載せる画面は、全部この撮影で実際に踏んでいる

## 文体について踏襲したこと

- 太字、斜体、表、`→` `／` `：` `▲` `▶` を使っていない（本文の実測で 0 件）
- 見出し以外に絵文字を入れていない
- 箇条書きは手順のときだけ。それ以外は文章で書いている
- 専門用語を日常の言葉に置きかえている。ローカルストレージ、Service Worker、PWA、キャッシュといった語は本文に出していない

- 効果を言い切らず、作者の見立てとして書いている

## 撮影中に見つけた不具合（記事とは別のコミットです）

更新の帯（「あたらしい ばんが あります」）が、狭い画面で 1 文字ずつ縦に並んでいました。

原因は横位置の取り方です。位置を固定した箱に幅の指定が無いと、幅の上限は「左端から画面の右端まで」になります。左端を 50% に置いていたため上限が画面の半分になり、`max-width` の 460px が効いていませんでした。実測では 390px の端末で帯が 195px、320px の端末で 161px まで縮み、文言の側が幅 0 になって高さ 250px の縦書きのようになっていました。

左右の両方を指定して `margin` を auto にする形へ直し、あわせて狭いときはボタンが下の段へ回るようにしています。直したあとの実測は、320px で帯 294px・文言 260px の 1 行、390px で帯 359px・文言 325px の 1 行です。

この修正は記事とは別のコミットに分けてあります。記事の画像 22-update.png は修正後の画面です。公開の前にこの修正を反映してください。

変更したのは `src/pwa.js` と、あわせて `public/sw.js` の `APP_VERSION`（v4 から v5）です。README の「リリースのたびに上げる」に従いました。ほかの修正とまとめて出すつもりで、まだ上げたくない場合は、そこだけ戻してください。
